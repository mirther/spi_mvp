# Operation Types — MVP

## 1. Назначение классификации

Тип операции описывает **направление переноса данных между внешней файловой системой HPC, постоянным хранилищем Dataset платформы и оперативной памятью**. Это не классификация научных алгоритмов.

В обозначениях ниже:

- **HPC** — внешние файлы на файловой системе HPC, например исходный SEG-Y или экспортируемый SEG-Y;
- **DB** — постоянное хранилище Dataset платформы. Амплитудные данные физически хранятся в собственном бинарном формате на HPC; PostgreSQL хранит каталог, метаданные, версии, связи и пути/идентификаторы хранения;
- **RAM** — оперативная память вычислительного узла, где находится рабочее представление Dataset во время выполнения SLURM Job.

> `DB` в направлениях операций не означает, что амплитудные массивы записываются в таблицы PostgreSQL. PostgreSQL и бинарное хранилище Dataset — разные физические компоненты постоянного хранения.

## 2. Типы операций MVP

| Тип операции | Направление | Основной модуль | Назначение |
|---|---|---|---|
| `import_dataset` | HPC → DB | `SEGYIN` | Импортирует зарегистрированный внешний файл SEG-Y во внутренний формат Dataset платформы. Читает амплитуды и заголовки, разбирает структуру файла, записывает полное содержимое Dataset в постоянное хранилище и регистрирует Dataset с первой версией в PostgreSQL. Регистрация исходного физического файла как `Data Asset` выполняется отдельно. |
| `load_dataset` | DB → RAM | `IN` | Загружает сохранённый Dataset или назначенную часть Dataset в оперативную память как рабочий объект (`Working Dataset`). Модулям обработки не требуется самостоятельно задавать путь к физическим файлам или разбирать внутренний формат хранения. |
| `save_dataset` | RAM → DB | `OUT` | Сохраняет полное текущее состояние `Working Dataset` во внутреннем бинарном формате на HPC, включая амплитуды, заголовки и структуру данных. В PostgreSQL регистрируется новая неизменяемая `Dataset Version` и её метаданные. |
| `export_dataset` | DB → HPC | `SEGYOUT` | Читает сохранённый Dataset из внутреннего хранилища и формирует внешний файл в выбранном формате. Для MVP целевой формат экспорта — SEG-Y. Экспортированный файл может быть зарегистрирован как `Data Asset`. |

## 3. Настройки связей Pipeline

Разделение Dataset на partitions и объединение partitions не являются самостоятельными типами операций или модулями. Они задаются настройками связей между `Pipeline Nodes`:

- настройка разделения определяет таблицу partitions и правила распределения трасс между заданиями;
- настройка объединения указывает, что результаты нескольких входящих partitions должны рассматриваться следующим узлом как один логический Dataset;
- одна строка Partition Definition соответствует одной partition и одному SLURM Job в рамках соответствующего Node Run.

## 4. Рабочее состояние Dataset

`Working Dataset` — runtime-представление сохранённого Dataset в RAM конкретного SLURM Job. Оно содержит фактические амплитудные массивы, заголовки, технические метаданные и необходимую структуру/индексацию трасс.

- `load_dataset` создаёт рабочее представление из сохранённого Dataset.
- В рамках MVP встроенные научные преобразующие модули типа FILTER, SORT и FOURIER не входят в поставляемый набор операций.
- `save_dataset` сохраняет полное текущее рабочее состояние как новую версию Dataset.
- Если рабочее состояние не сохранено через `save_dataset`, изменения в RAM не становятся постоянной версией Dataset.

## 5. Перспективный тип расширения — вне MVP

**RAM → RAM, с возможностью прямого вывода RAM → HPC**.

Этот тип предназначен для пользовательских вычислительных модулей, которые получают `Working Dataset`, выполняют вычисления в памяти и возвращают изменённое рабочее состояние. Отдельные модули смогут дополнительно записывать самостоятельные результаты (`Artifact`) непосредственно в файловую систему HPC.

Примеры будущих пользовательских модулей: FILTER, SORT, NORMALIZE, FOURIER и другие научные алгоритмы. Такие модули не входят в поставляемый MVP-набор; пользователи смогут создавать их позднее по отдельным техническим гайдлайнам платформы.

## 6. Что не является типом операции

- Научное назначение алгоритма (фильтрация, сортировка, нормализация, спектральный анализ) само по себе не определяет тип операции.
- Разделение Dataset на partitions и объединение partitions не являются отдельными типами операций. Это настройки связей между `Pipeline Nodes`.
- `Artifact` — вид самостоятельного результата, а не тип операции MVP.

## 7. Принцип хранения

Внутреннее постоянное представление Dataset использует собственный бинарный формат платформы. Физические бинарные данные и их части хранятся на HPC; PostgreSQL содержит структурированные сведения, необходимые для идентификации, поиска, версионирования и чтения Dataset. Внутренняя организация бинарного формата (один файл или набор файлов, манифест, индексы и разбиение на части) определяется отдельно.
